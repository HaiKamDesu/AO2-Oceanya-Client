## panel catalog

**Also called:** "panel catalog", "panel placement", "where is the IC log positioned", "move a main window region", "panel id"

**Status:** Confirmed

`OceanyaClient/Features/Theme/OceanyaPanelCatalog.cs` owns each GM panel's stable id, display name, minimum size and default placement; `OceanyaPanelLayout.ApplyDefaultPlacements` writes `Canvas.Left/Top/Width/Height` onto the controls. `MainWindow` calls `ApplyPanelCatalogPlacements()` right after `InitializeComponent()`, and those geometry attributes NO LONGER exist in `MainWindow.xaml` — change placement in the catalog, not the XAML. Registered ids: `ic_log`, `ooc_log`, `clients_list`, `shout_backdrop`, `shout_holdit`, `shout_objection`, `shout_takethat`, `shout_custom`, `ic_settings` (+17 IC sub-panels: `ic_showname`, `ic_message`, `ic_emote_grid`, `ic_check_*`, `ic_combo_*`, `ic_button_*`), `bottom_bar` (+ `bar_check_*`/`bar_button_*`), `clients_title`, `clients_add`, `clients_remove`, `dredd_row`, plus runtime `custom_image_*`/`custom_color_*` (defaults reproduce the historic fixed layout exactly). Panel ids are referenced by shared theme files: renaming one breaks existing themes and needs a theme compat bump. **OOC block is layered:** `ooc_log` (grey background only), `ooc_chat` (transparent text), `ooc_stream_backdrop` (translucent black header bar — split out of `lblStream`'s own Background), `ooc_stream_text`, `ooc_message`, `ooc_showname`, `ooc_server_console`; the `OOCLog` control collapses itself after handing them over but stays in the tree for its code-behind. `ic_settings` is now just the Oceanya logo (`imgOceanyaLogo`), and `ICMessageSettings` collapses itself the same way. Extracted panels live in `OceanyaClient/Components/Panels/`: `ConnectionInfoPanel` (chips; host calls `SetConnectionInfo`), `DreddFeatureRowPanel` (raises `OverlaySelected`/`StickyOverlayChanged`/`ConfigRequested`/`ViewChangesRequested`; `DreddOverlaySelectionItem` now lives in that namespace), `ClientsListPanel` (`AddClientRequested`/`RemoveClientRequested`, `ButtonGrid`, `SetHeaderContextMenuFactory`), `ShoutRowPanel` (`SelectedShoutModifier`/`ClearSelection`). **NAMING TRAP FIXED:** MainWindow's `PageButtonGrid` was called `EmoteGrid` but holds CLIENT buttons (the emote grid is inside `ICMessageSettings`); it is now `ClientsListPanel.ButtonGrid`, panel id `clients_list`. Extraction pattern: panel owns visuals + raises events, host keeps logic and pushes state in — never expose raw child elements. Tests that reach into MainWindow internals must follow (`Phase1/Phase2ReleaseConfidenceTests.AddClientToWindow` uses `ClientsList.ButtonGrid`; `MainWindow_AndChildControls_HaveCoreAutomationIds` scans `Components/Panels/*.xaml` too). `BottomStatusBarPanel` (exposes `AreaNavigatorAnchor`/`MusicListAnchor`; MainWindow sets `Popup.PlacementTarget` in code since ElementName binding cannot cross the panel boundary). **Panel XAML must carry its own resources** — a panel cannot see MainWindow's ResourceDictionary (moving markup using `{StaticResource CompactIconButtonStyle}` without the style threw XamlParseException; the MainWindow-constructing Phase1/2/3 tests catch it). Still inline: area navigator + music list popups (overlay surfaces, not layout panels). **LAYOUT EDIT MODE:** pencil toggle `Main.EditLayout` at the right of the bottom bar -> `OceanyaPanelEditModeController` (`Features/Theme/OceanyaPanelEditMode.cs`) overlays each visible panel; drag to move, bottom-right grip to resize, clamped by descriptor minimums via `OceanyaPanelLayout.SanitizePlacement`. Persists to `SaveData.OceanyaThemeLayout` on drop and on exit; `OceanyaPanelLayout.ApplyLayout` = defaults then saved layout on top; `ResetLayout()` restores defaults. Right-click a panel in edit mode for default position/size restores. **Reset = FULL theme reset** via `MainWindow.ResetThemeLayoutToDefaults` (editor's Reset all delegates through `FullResetHandler`; settings button raises `PanelLayoutResetRequested`): clears placement/stacking/styling (restores live controls from `OceanyaPanelStyleApplier` baselines), clears `surfaceSizeFollowsWindow` BEFORE deactivating (else the deactivate path persists the resized window into the fresh layout and the size survives the reset), RESTORES EVERY PANEL'S `Visibility` explicitly (an empty layout has no hidden entries so nothing else un-hides them), deletes user-added panels, turns off `GMViewportRenderInPanel`, re-applies non-theme conditional hiding (debug button, test-mode checkboxes, Dredd row), and leaves edit mode via `Deactivate(persistLayout: false)` FIRST — a plain deactivate persists current positions and wrote the old layout back over the reset. The AO2 viewport theme is NOT touched. **Toolbar z-index** (`EditToolbarZIndex`) must exceed `ResolveOverlayZIndex` (100000 + order) or overlays eat its clicks. **Surface growth:** `MainWindow.RecalculateSurfaceSizeFromPanels` unions all panel rects after every change, shifts the layout back into view when a panel goes past the left/top edge, and grows the surface (never below stock size) — so `SanitizePlacement` clamps SIZE but deliberately allows negative positions. **Responsive panels:** `IcLogPanel`/`OocLogPanel` own their background art and stretch the log inside (ICLog/OOCLog no longer hard-code Width/Height); **`OocLogPanel`'s hosted log keeps `Margin=0,0,0,71`** so the log still ends at y=262 of the 333-tall backdrop like 7.12, since the OOC input strip that filled the rest is now the separate `ooc_message`/`ooc_showname`/`ooc_server_console` panels (defaults 262/281 — the exact 7.12 spots; `ooc_server_console` is 380,281,129x17 because 7.12's DockPanel had `LastChildFill` so it took the width left over beside the 93px showname, NOT a 83px button. Guarded by `Catalog_DefaultPlacementsMatchTheHistoricFixedLayout`); `ClientsListPanel` is a 3-row grid (centered title, centered +/- pair, grid filling the rest) and `PageButtonGrid.EnableAutomaticPageSize(itemSize)` recomputes rows/cols on SizeChanged. **Shouts are 4 separate panels** (`ShoutButtonPanel` + `ShoutSelectionGroup` for radio behavior; automation ids applied at runtime via `SetAutomationIdentity`, which is why `MainWindow_AndChildControls_HaveCoreAutomationIds` scans code-behind too). **Exits from edit mode:** floating Done/Cancel/Reset-all toolbar at z-index 10001 plus Escape (Cancel = `CancelEditing`, which restores a JSON snapshot of the layout taken at Activate — edits persist as they happen, so there is nothing to undo step by step — then calls `LayoutRestoredHandler`) — the pencil that enables edit mode sits UNDER the bottom bar overlay, so without these you are trapped. **Hide/show:** right-click -> Hide panel actually hides it (edit mode too); restore from the toolbar's `Hidden controls` list. Persisted via `OceanyaPanelPlacementState.IsHidden`, applied at startup by `ApplyHiddenPanels`. **PANEL KINDS:** `OceanyaPanelDescriptor.Kind` decides resize rules + which reusable settings popup the menu opens (`OceanyaPanelSettingsDialogs`: Font = family/size/bold/italic/underline/colour, Image = image/scaling/opacity/background colour (also offered for user-added Static panels), Grid = item size). All dialogs use the shared two-column `CreateFieldGrid`/`AddField` plus the colour-picker and opacity rows. Never put lists of literal values in the context menu. TextInput/Dropdown/TextToggle are width-only (height from font via `OceanyaPanelStyleApplier.ResolveTextPanelHeight`). Settings persist on `OceanyaPanelPlacementState` (`FontSize`/`FontFamily`/`IsBold`/`ImageScaling`/`ImagePath`/`ItemSize`/`ZOrder`) and apply via `OceanyaPanelStyleApplier`. **Z-ORDER:** `ZOrder` -> `Panel.SetZIndex`, menu has bring-to-front/forward/backward/to-back, overlays use `ResolveOverlayZIndex` (10000 + order) and are OUTLINE-ONLY with a hover highlight (stacked translucent fills made overlapping panels unreadable); panel name is the overlay tooltip, grip is 5px. **VIEWPORT IN MAIN WINDOW:** checkable `Render viewport in main window` (via `ExtraPanelMenuItemsProvider` -> `OceanyaPanelMenuEntry` with `IsChecked`) REPLACES the viewport button — collapses `bar_button_viewport` and moves `AO2ViewportWindowContent` into `ViewportPanelHost` (panel id `viewport`); forces PiP off AND `GMViewportWindowPreviewPriority = false` (no separate window to represent); persists as `SaveData.GMViewportRenderInPanel`, re-applied at startup. **RESET restores styling too:** `OceanyaPanelStyleApplier.CaptureBaseline` snapshots each panel's untouched fonts/images/z-order on first restyle and `RestoreBaseline` puts them back, because styles are applied onto live controls; reset also un-hides panels and keeps user-added ones. Leftover controls now panels: `ding_button`, `ooc_divider`, `ic_catchphrase`, `ic_settings_backdrop`, `ic_loremaster`. **USER-ADDED PANELS:** toolbar `Add panel` or right-click empty space -> image (file picker) or solid colour (`AOCharacterFileCreatorWindow.ShowSolidColorPickerDialog`, takes/returns a `Color`); stored in `OceanyaThemeLayoutState.CustomPanels`, built by `OceanyaCustomPanelFactory`, registered via `OceanyaPanelCatalog.RegisterCustomPanel` (`Panels` includes them, `BuiltInPanels` does not — tests assert on `BuiltInPanels`). **RIGHT-CLICK TRAP:** the empty-space add-panel handler must skip clicks landing on a panel overlay (`IsOverlayElement`) — WPF opens ContextMenus on `MouseRightButtonUp`, so marking it handled unconditionally swallowed every panel's own menu and only the add-panel menu appeared. **Dialog sizing:** `CreateEmoteDialog` clamps requested size to `ResolveDialogSpace` (work area / UI scale), and `BuildStyledDialogContent` wraps the body in a `Viewbox` (Uniform, DownOnly) instead of a `ScrollViewer` — the ScrollViewer was why dialogs opened cropped and needed scrolling/resizing; now content scales down to fit and stays 1:1 at or above natural size. **Growing left/up also moves the host window** (`MoveHostWindowForSurfaceGrowth`) so untouched panels stay put on screen. **IC settings split:** `ICMessageSettings.ExtractPlaceableControls()` + `MainWindow.AdoptIcSettingsPlaceableControls()` REPARENT its showname/message/emote grid/4 checkboxes/6 dropdowns/4 buttons onto MainCanvas — reparenting keeps all of ICMessageSettings' fields and handlers working; only the layout parent changes, and `ic_settings` keeps just the background art. Gotcha: `UpdateDreddFeatureVisibility` still moves the bottom bar by the Dredd row height and overrides a custom position. Tests: `UnitTests/OceanyaPanelCatalogTests.cs`.

## theme scope

**Also called:** "theme scope", "what can an ao2 theme change", "ao2 theme assets", "courtroom_fonts.ini", "chat_config.ini", "theme resolution order", "subtheme", "misc pack", "what can't we theme", "theme gaps"

**Status:** Confirmed

Reference map: `Documentation/AO2ThemeCapabilities.md` (its "What we still cannot reproduce" section is the authoritative gap list: widgets for features we lack, stylesheet features with no field, structural differences) — the full `get_asset_paths` resolution chain (character -> subtheme misc -> theme misc -> subtheme -> base misc -> theme -> default theme -> bare -> placeholder, `AO2-Client/src/path_functions.cpp:175`; the same chain resolves INI keys via `get_config_value`, so a subtheme can override one key and inherit the rest), every `courtroom_design.ini` identifier by area, `courtroom_fonts.ini` keys, `chat_config.ini` colour markup, `courtroom_sounds.ini`, image/animation slots and asset folders, and a fidelity table. `courtroom_stylesheets.css` is NOT translatable (no Qt stylesheet engine in WPF). ## use my AO2 theme in oceanya

**Also called:** "use my AO2 theme in oceanya", "import ao2 theme", "translate ao2 theme", "courtroom_design.ini widget positions"

**Status:** Confirmed

Investigation doc: `Documentation/AO2ThemeImport.md`. AO2 themes are absolute `x, y, w, h` per widget in `courtroom_design.ini` (`AO2-Client/src/courtroom.cpp` `set_size_and_pos` -> `text_file_functions.cpp` `get_element_dimensions`, scaled by `theme_scaling_factor`; missing entry means AO2 HIDES that widget). `courtroom = 0,0,W,H` is the window size. Same model as `OceanyaThemeLayoutState`, so import is a mapping job — doc holds the full identifier->panel table. Gotchas: `showname`/`message` are relative to `chatbox`, `music_name` relative to `music_display`, keys are inconsistently cased, `courtroom_stylesheets.css` cannot translate. Chatbox/chat_config/sounds/viewport art are ALREADY consumed by `AO2ChatPreviewResolver`/`AO2ViewportAssetResolver`. Reference themes live in `<AO install>/base/themes` (61 in the dev install; GrayGarden is the most heavily customised example, imports 30 panels). **IMPLEMENTED:** `OceanyaClient/Features/Theme/Ao2ThemeLayoutImporter.cs` (`ParseDesignFile`/`Translate`/`ImportTheme`) + Settings → Interface → Panel Layout (theme picker, Import, Reset; `SettingsWindow.PanelLayoutChanged` → `MainWindow.ReapplyPanelLayoutFromSavefile`). **Theme roots are `<base>/themes/<name>` — `GetAo2ThemeScanFolders()` returns BASE folders, so the `themes` segment must be added or no theme is ever found.** Policy: unmentioned panels get REAL hidden entries (a missing entry would leave them visible at Oceanya defaults), imported rects shift right by `ClientsStripWidth`=54 with the clients strip packed on the left (no AO2 equivalent), cosmetic Oceanya-only panels hidden, import enables `GMViewportRenderInPanel`. **Appearance is imported too** (`ApplyThemeAppearance`): per-panel art via AO2's `setImage` names (`holdit`/`takethat`/`custom`/`realization`/`screenshake`/`pair_button`/`courtroom_settings` — NOT the design.ini identifiers) with `*_selected`/`*_pressed` as the checked image and AO2's extension probe order, typography from `courtroom_fonts.ini` (size/font/bold/colour, `r, g, b` -> #AARRGGBB via `ConvertRgbTripletToHex`), `courtroombackground` -> a LOCKED lowest-z custom image panel (`ThemeBackdropPanelId`) sized to the theme's own rect (a surface-wide fill stretched across the extra clients strip and stopped lining up with the widgets), and the import switches `config.ini` `theme` so the chatbox/viewport half of the look matches. **HARD RULE: the importer may only write settings the editor can also set by hand** — add the editor control first (per-panel popups; backdrops are locked image panels — `IsLocked` + `Lock in place` in the panel menu — not a bespoke surface setting). **`IsLocked`** hides ALL overlay chrome (no border/grip/hover) and blocks dragging while keeping the right-click menu; **`IsClickThrough`** sets `IsHitTestVisible=false` so a panel never eats clicks meant for what is behind it (imported backdrops get both). The `viewport` panel's default z-order is LOW (5) because AO2 draws the viewport behind its widgets — a high order covered IC message/showname and swallowed their clicks. **STYLESHEETS:** `Ao2StylesheetTranslator` maps Qt class selectors (`QLineEdit`/`QComboBox`/`QCheckBox`/`QLabel`/`QTextEdit`/`QListWidget`/`QWidget`) onto panel kinds and writes `background-color`/`color`/`font-family`/`font-size`/`font-weight` into the SAME per-panel fields the popups expose (bulk edit, not a second engine); pseudo-states, sub-controls, `[x=...]` selectors, borders, padding and `image:url()` are ignored until a field exists. Reachable via `Stylesheet...` on the edit toolbar. **Image overrides** fall back to painting a shape's `Fill` with an ImageBrush (and clearing its `OpacityMask`) when a button's face is a masked `Rectangle` rather than an `Image`, and imports set `ImageScaling=Fill` because `AOButton::updateIcon` scales art with `Qt::IgnoreAspectRatio`. **Baselines must be re-captured on the deferred pass** (`AppendBaseline`) — template faces do not exist at first capture, so without it reset could not restore original button art. **Positioning rules:** all imported rects shift right by `ClientsStripWidth`=54 (backdrop too, so alignment holds); one-rect-to-many panels go through `ApplyCompositeRegions` (AO2's single `server_chatlog` lays out our ooc background/header/header-text/chat inside it, otherwise the block tears apart); mapped-but-missing essentials (`EssentialMappedPanelIds`: IC message/showname, emote grid, 6 dropdowns, OOC message/showname) are parked in the left strip instead of hidden; Oceanya-only functional panels pack into the strip (`PlaceFunctionalPanels` reserves the tail height below the clients list via `ResolveStripTailHeight` — a fixed 4-row reservation pushed the last controls off the bottom — and clamps overflow to the bottom edge so it overlaps rather than disappearing); cosmetic ones hide. **SIZING:** imported surface is `courtroom.H + TopBarHeight`(24) tall and `W + ClientsStripWidth`(54) wide — the AO2 `courtroom` rect is the CANVAS here, the connection-info bar sits above it, and without the 24 the theme's bottom widget row is clipped off the window. **FONTS:** `courtroom_fonts.ini` `showname`/`message` are the VIEWPORT CHATBOX fonts (already handled by `AO2ChatPreviewResolver`) and are deliberately NOT mapped onto `ic_showname`/`ic_message` — doing so rendered the input boxes at chatbox size. **EMOTE GRID:** AO2 fits FIXED-size buttons (`emote_button_size` + `emote_button_spacing` from design.ini, theme-chain fallback `40,40`/`9,9`, `AO2-Client/src/emotes.cpp`), it does not stretch them; the importer writes that into the emote grid's `ItemSize` and `PageButtonGrid.EnableAutomaticPageSize` derives rows/cols. The button face was hard-coded 40x40 in `ICMessageSettings.CreateEmoteButton`'s template (now `Stretch=Fill`) and `PageButtonGrid.xaml`'s grid area was in a vertically scrollable ScrollViewer (infinite height collapsed the star rows) — both fixed, do not reintroduce. **1x1 TRANSPARENT ART IS FAITHFUL:** GrayGarden ships 81-byte 1x1 PNGs for `realization`/`screenshake`/`pair_button`/`holdit`/`custom` and paints them into `courtroombackground` — an invisible imported button is usually correct, not broken. **Qt CHECKBOX font-size is indicator sizing, not text size** (GrayGarden asks 50px on a hidden label): `Ao2StylesheetTranslator` drops font declarations for TextToggle panels and for any rule with `color: transparent`. **Image/scaling overrides defer at `DispatcherPriority.Loaded`** — at Normal the callback ran before the control template existed and silently applied nothing. **`MainWindow.RestoreMainWindowForegroundIfOwned()`** runs after `ReapplyPanelLayoutFromSavefile` because applying a layout can hide the viewport window and re-run taskbar-preview mode, which handed the foreground to another process and looked like the app minimizing itself on theme import. **THREE-STATE ART:** panels carry resting/hover/selected images (`ImagePath`/`HoverImagePath`/`CheckedImagePath`, all three in the Image popup); CSS-heavy themes ship a 1x1 TRANSPARENT base image, paint the resting look into `courtroombackground`, and give real art only to `:hover`/`:pressed` — GrayGarden's "buttons invert while pressed" is `hover/topleft.png`. WPF template triggers can't be rewritten from data, so `OceanyaPanelStyleApplier.ApplyStateArt` swaps the face on MouseEnter/Leave/Checked and registers an undo via `PanelStateOverrides` — **any non-DP setting MUST register an undo there or reset cannot restore it** (grid paging does too). **`ResolveThemeImage` probes every extension INSIDE one theme before the default theme** (AO2's `get_image_suffix(get_theme_path)`); extension-first handed GrayGarden's `holdit.png` to `default/holdit.gif`. **STYLESHEET reach:** class selectors → panel kinds; `[x=][y=][width=][height=]` → the single panel whose AO2 rect matches (needs `Ao2ThemeImportResult.Widgets`, so import-only — a hand-picked stylesheet skips them); `:hover`/`:pressed`/`:checked`/`:on` → hover/selected image; `image:url()` resolved against the AO install root. `QListWidget`/`QListView` deliberately UNMAPPED (AO2's list widgets are music/area/pair/mute lists, not panels — mapping them painted the emote grid + clients list). **DROPDOWN POPUP:** `ImageComboBox`'s popup Border is hard-coded white and its rows inherit the control Foreground, so a theme asking for white text gave white-on-white; `ApplyDropdownPopupColours` makes the popup follow the panel background (reached via `Template.FindName("Popup")` — popup content is outside the visual tree until first opened, and is baseline-captured the same way). **EMOTE ARROWS ARE PANELS** (`ic_emote_prev`/`ic_emote_next`, from `PageButtonGrid.ExtractPagingControls()`); defaults are their exact in-grid 7.12 rects and the grid keeps that inset unless `ReservePagingSpace` is cleared (grid popup checkbox; import clears it). **GRID METRICS ARE A `w,h` PAIR + per-axis spacing** (`ItemSize`/`ItemHeight`/`ItemSpacingX`/`ItemSpacingY`): AO2 keeps items at that exact size and leaves slack empty, it does NOT stretch them. **Fonts apply to Static panels too** (the logs) but only text-box kinds take their HEIGHT from the font — resizing a log to its font collapsed a 350px panel to one line. **HOVER != SELECTED:** hover art is painted only while the panel is NOT checked (AO2 leaves a checked button alone on hover; painting it anyway looked like the button un-pressing itself). **`PanelStateOverrides.Replace` (not `Register`) for handlers** — a layout is applied several times per session and keeping only the FIRST undo left every later handler set attached forever, so reset stopped working and handlers stacked; `RestoreBaseline` also runs `PanelStateOverrides.Restore` BEFORE its early return, since a panel with no visual baseline can still carry handlers. **Extracted paging buttons must carry their Style locally** (`ExtractPagingControls` pins it) — `PageButtonGrid`'s implicit `Button` style is resolved via the ancestor chain they leave when reparented. **`SetPagingReservation` spans the item area, never resizes row/column definitions** — `UpdateButtonVisibility` adds/removes definitions per scroll mode so index 1 is not reliably the content cell; zeroing the wrong one made the item area 0px tall and the emote grid vanished after import (`UnitTests/PageButtonGridLayoutTests.cs`). A themed button face clears a string `Content` so glyph labels don't sit on the art (`ContentControl.ContentProperty` is baseline-tracked). **FONTS ARE POINTS:** `courtroom_fonts.ini` uses `QFont::setPointSize`, WPF uses DIPs — importer multiplies by 96/72 (a raw copy rendered text 25% small and clipped the OOC header, whose panel height hugs the font). **BORDERS ARE TRI-STATE:** `BorderThickness` negative = leave the control's own, 0 = genuinely remove; import sets 0 on every mapped panel because a Qt widget has no frame unless the stylesheet draws one, then CSS puts back what the theme asks for (this is what removed the emote grid's grey outline). **NEW STYLE FIELDS:** `BorderColor`/`BorderThickness`, `IndicatorImagePath`/`CheckedIndicatorImagePath` (checkbox tick box via a generated template; dropdown arrow via `btnDropdown`'s background), `ImagePath` on a TextToggle = the checkbox CAPTION drawn as art, `ScrollbarTrackColor`/`ScrollbarHandleColor`/`ScrollbarBorderColor` (applies `Styles/OceanyaThemedScrollBar.xaml` + brushes into the PANEL'S OWN `Resources`, undone via `PanelStateOverrides`). Text-panel background is also pushed onto the inner `TextBox`/`ComboBox`/`CheckBox` — painting only the container left it hidden behind the control's own brush. **Static panels get the Font dialog** (logs need fonts + scrollbars). **`SetFaceArt` tries Image → masked Shape → icon-font glyph** (glyph = paint the face's background + hide the TextBlock); the settings/refresh buttons are glyph faces, which is why they ignored theme art. **Sub-controls are class-gated** (`IsSubControlOfClass`): `::down-arrow` is a dropdown arrow on QComboBox but a scroll arrow on QScrollBar — ungated it put scroll arrows on every panel with a scrollbar. **BASELINE TRAP: `Control.Background`, `Border.Background` and `Panel.Background` are the SAME DependencyProperty** (AddOwner) — excluding `Panel.BackgroundProperty` from the Control branch silently dropped every control's background from the baseline and broke reset. **OOC HEADER = AO2's MUSIC DISPLAY, BUT ONLY WHEN IT IS ONE:** in the DEFAULT theme `music_display = 490,0,224,26` sits directly on `server_chatlog = 490,1,224,277` (same x/width) with `music_name` (coords RELATIVE to the display) as its label — that IS our black bar + header text, and `music_display.webp` is the bar art. A theme may instead repurpose the widget as a window-sized decoration (GrayGarden: `0,0,1262,700`), so `TryPlaceMusicDisplayHeader` guards on `IsHeaderShaped` (height ≤ max(32, oocHeight/3) AND overlaps the log's column): header-shaped → backdrop takes the display rect + art and `ooc_chat` gets the WHOLE chatlog rect; otherwise → `ooc_stream_backdrop` is HIDDEN (nothing describes it), the text keeps the top strip, and the art is imported as a DECORATION. **DECORATIONS:** `DecorationImages` (AO2 `AOImageDisplay` widgets with no Oceanya control) import as locked click-through image panels at `ThemeBackdropZOrder+n`, same machinery as the courtroom backdrop; skipped when the header mapping already claimed the art. **AREA/MUSIC LISTS ARE PANELS:** AO2's `area_list`/`music_list` are the LISTS, not buttons — `area_list`/`music_list` panels (`AreaListPanelHost`/`MusicListPanelHost`) with `Render area/music list in main window` menu toggles that REPARENT the popup content (`ApplyListRenderInPanel`, `SaveData.GMAreaListRenderInPanel`/`GMMusicListRenderInPanel`) and hide the bar button; `bar_button_areamusic` (A/M switch, `switch_area_music`) toggles which one shows when both are in-window (`GMAreaMusicSlotShowsMusic`). **BOTH LISTS SHARE AO2's `music_list` RECT** — `courtroom.cpp` does `set_size_and_pos(ui_area_list, "music_list")` then the same for `ui_music_list`; the `area_list` identifier is only a FONT key (`set_font(ui_area_list, "", "area_list", ...)`), so a rectangle under that name describes nothing AO2 draws (it is in `IdentifiersHandledElsewhere`). **OFF-SURFACE COUNTS AS HIDDEN:** `OceanyaPanelEditModeController.IsFullyOffSurface` — a panel entirely outside the surface joins `hiddenPanelIds` — re-derived by `RefreshUnreachablePanels` at Activate, on drop, in `RebuildOverlays` (so a visibility/layout change is caught) and on `Surface_SizeChanged`; `offSurfacePanelIds` tracks entries added for that reason so they un-list themselves when back in view and never swallow a deliberate hide — gets no overlay, is labelled "(off-screen)" in the Hidden controls list, and restoring it runs `BringPanelIntoView` (centre + bring-to-front) because showing it in place would re-hide it. **HIDDEN-BY-DEFAULT PANELS:** `OceanyaPanelCatalog.IsHiddenByDefault` — panels that exist but the stock layout does not show; honoured by `ApplyHiddenPanels`, `IsHiddenByLayout` and the reset path, so a theme or a user un-hides them. Current set: `bar_button_areamusic` (`switch_area_music`), `bar_button_mute` (`mute_button`, says muting is unimplemented), `bar_button_evidence` (`evidence_button`, reports evidence is unsupported — that IS its job), `bar_button_reloadtheme` (`reload_theme`), `bar_button_changecharacter` (`change_character` → `SelectIniPuppetManuallyAsync`, extracted from the client menu so both paths share it), `bar_button_callmod` (`call_mod` → `AOClient.CallModerator`: `ZZ#%`, or `ZZ#<reason>#-1#%` when the server advertises `modcall_reason`), and `slider_music/sfx/blip_volume` (`*_slider`; live preview while dragging, `AudioSettings.PersistVolume` writes BOTH config.ini and the savefile on release since config.ini wins on read). **Themeable extra buttons MUST use the `ThemeableFaceButton` style** (`MainWindow.xaml`) — a default WPF Button template has no Image/Shape/Panel, so `SetFaceArt` finds nothing to paint and theme art silently does not apply. **THEMED ART CLEARS THE CONTROL'S CHROME** (`ClearThemedButtonChrome`): an AO2 button has no fill/frame of its own (its art is often a 1x1 transparent with the look painted into `courtroombackground`), so applying an image drops our default background/border unless the theme set one — otherwise a coloured square showed behind/instead of the art (mute + evidence buttons). **SLIDERS:** `QSlider::groove` → `ImagePath` (widget-wide art), `::handle` → `IndicatorImagePath`; `ApplySliderArt` injects `Styles/OceanyaThemedSlider.xaml` + brushes into the panel's Resources like the scrollbars. Slider CAPTIONS are art too (`sliders/labels.png` 370x12 on `blip_label`) → `slider_music/sfx/blip_label` image panels; `QSlider` is mapped panel-by-panel via `SelectorPanels` (mapping it by KIND would hit the logs) and `QLabel` maps to BOTH TextToggle and ImageButton kinds. **SLIDER FILL IS `::sub-page`/`::add-page`** (not part of the groove art): GrayGarden's `meter.png` is only the tick marks and `handle.png` the diamond, so without the two pages the slider looked empty; `FillColor` = sub-page, `BackgroundColor` = add-page, `BorderColor` = both page borders, and sliders are their own `OceanyaPanelKind.Slider` with a `Slider settings...` dialog. **IN-PANEL LISTS ALSO NEED THEIR MinWidth/MinHeight CLEARED** — the music popup's surface has `MinHeight=300`, so inside a 209px panel it overflowed and was CLIPPED (ClipToBounds) instead of scrolling, which is why "there is no scrollbar" survived the ViewportSize fix. **LOG COLOURS ARE PUSHED, NOT INHERITED:** the logs write runs with explicit brushes, so `TextColor`/`SenderColor`/`SelfNameColor`/`TimestampColor` reach them via `ICLog`/`OOCLog.SetThemeColors` from `MainWindow.ApplyLogThemeColors` (null field = keep the control's own, so an empty layout restores defaults). `courtroom_fonts.ini` is MERGED WITH THE DEFAULT THEME PER KEY (`ParseMergedThemeFile`) because AO2 resolves each key through the chain — 51 of 61 installed themes set `ic_chatlog_color` but only 2 set any name/timestamp colour, so reading one file left every other theme on OUR colours instead of AO2's. AO2 keys: `*_color` body, `ic_chatlog_showname_color`/`ms_chatlog_sender_color` → `SenderColor`, `server_chatlog_sender_color` → `ServerNameColor` (AO2 picks by the CT packet's colour flag — "0" plain message, "1" server — not by which log it is), `ic_chatlog_selfname_color` → `SelfNameColor`, `ic_chatlog_selftimestamp_color` (else `ic_chatlog_timestamp_color`) → `TimestampColor` (our only timestamp-ish detail is the `[GM]` marker on your own lines). `ApplyBackgroundColor` also paints whatever is ACTUALLY painting inside the control (`PaintExistingBackgrounds`, falling back to the first container) — the log panels put their artwork on a Grid several levels down, behind the UserControl's template border, so painting the control's own brush left the picture there. Existing log lines are repainted too: each run carries a `LogRunRole` in its `Tag` and `LogRunRecolorer` walks the stored documents on `SetThemeColors`, so applying a theme does not leave the log in two colour schemes (clearing repaints back to the built-in colours; IC message colours are tagged `None` and never touched). `ApplyLogThemeColors` runs at STARTUP too (in `ApplyPanelCatalogPlacements`), not only on reapply. IC MESSAGE colours (green/red/blue) are NOT themed — they are protocol, from `chat_config.ini`. Import also clears the log panel backgrounds (AO2 logs are transparent over the courtroom art), and a Static panel's font dialog exposes all of it plus a background image. **OOC CHAT TAKES THE WHOLE `server_chatlog` RECT** unless the header text actually sits on top of it. **NO PRE-THEME FLASH:** `MainWindow` hides `MainCanvas` until the first deferred styling pass has run (`RevealSurfaceAfterFirstLayout`). **OOC HEADER SHOWS THE SONG** — it is AO2's music display, so `OOCLog.SetNowPlaying` carries the now-playing text (fed from `UpdateCurrentMusicDisplay`); `UpdateStreamLabel` (client name) is gone. Its text lives in a CANVAS (a Grid measures the child against its own width, so the name was only laid out as wide as the widget and looked cut off mid-word; the Canvas must be told to Stretch on BOTH axes since it has no desired size and a Label aligns content left AND centred — otherwise the viewport measures 0 wide, then 0 tall, and the header shows nothing) and the rebuild needs a RE-ENTRANCY GUARD (it rewrites the text → resizes the track → raises the size change that called it → the label flickered between "None" and its scrolling form). Its edge fade must use ABSOLUTE gradient mapping measured from the VIEWPORT (a relative gradient maps onto the bounding box of the rendered content — including the translated text — so the fade scrolled along with it; and the viewport's size settles a layout pass after the label's, so measuring early pinned the fade mid-widget). It reproduces AO2's `ScrollText` (`AO2-Client/src/scrolltext.cpp`): `"None"` when idle, margin = height/3 each side, scrolls ONLY when wider than that, one CONTINUOUS loop (name + `"   ---   "` drawn twice for a seamless wrap) at 2px/50ms after holding 64 steps, 15px edge fade — not a bounce, never trimmed. **`ApplyHiddenPanels` SETS VISIBILITY BOTH WAYS, EXCEPT FOR RUNTIME-OWNED PANELS** — only collapsing left a panel hidden by an earlier layout hidden when the next one wanted it (reset-then-import in ONE session lost the A/M switch, mute, evidence until a restart), but showing everything revealed what the app deliberately hides (Dredd row, debug button, test-mode checkboxes, viewport/list hosts, judge + dropdown-reset buttons). Those are in `OceanyaPanelCatalog.HasRuntimeControlledVisibility`: a layout may HIDE them, never SHOW them, and `MainWindow.ApplyConditionalPanelVisibility` re-applies their real rules after every layout apply. ONE OWNER PER PANEL'S VISIBILITY. **REPLACING A LAYOUT MUST DROP ITS QUEUED WORK:** styling runs on deferred callbacks, so reset-then-reimport in one session let the OLD layout's callbacks land after the new layout — and the fresh baseline then recorded themed values as "original", so it stayed broken; each callback carries a generation stamp (`OceanyaPanelStyleApplier.InvalidatePendingWork`, called from `RestorePanelStyleBaselines`). **OOC HEADER TEXT IS AO2's** (`AOMusicPlayer::playStream`): `None` / `[MISSING] name` / `[STREAM] name` / bare name, name = filename minus extension. **SHARED SEARCH BOX:** `area_music_search` ← AO2 `music_search` (one box for whichever list is shown); it filters BOTH — the music tree via its existing filter and the area rows via `MainWindow.ApplyAreaNavigatorFilter` (unfiltered rows cached in `areaNavigatorItems`) — and while the panel is visible with the music list in-window the list's OWN search box hides to reclaim the rows (`IsSharedSearchActive`). **DROPDOWN RESET BUTTONS:** `ic_combo_position/character/sfx_reset` ← `pos_remove`/`iniswap_remove`/`sfx_remove` (`evidencex` art), shown ONLY while that dropdown is off its default (`Courtroom::on_pos_dropdown_changed`), driven by `ICMessageSettings.DropdownDefaultStateChanged` + `MainWindow.UpdateDropdownResetButtons`. **SMALL-PANEL BEHAVIOUR:** `ApplyHostedListCompactMode` sheds list chrome by worth (decoration → command row; the music search box goes LAST) instead of scaling everything down; `ImageComboBox.RefreshCompactMetrics` scales row icon/text/arrow with the control (clamped to stock, arrow ≤ 1/3 width) and a theme's arrow width goes through `SetArrowWidthOverride` so the two do not fight; the arrow ToggleButton has its OWN template because the stock chrome painted a solid square over the arrow while open. **HP EVENTS ARRIVE ON THE CONNECTED CLIENT** — in single-internal-client mode that is `singleInternalClient`, never a profile, so `OnHealthChanged` is hooked where it is created (and per-bot in `AttachDirectClientMessageHandlers` for multi mode); hooking only profile clients meant the bars never repainted. **A SLIDER SKIPS THE GENERIC BACKGROUND/BORDER PASSES** — it expresses both through its own template (background = the EMPTY half of the track, border = the track frame), and the generic deferred `ApplyBorder` was clearing the frame the template had just drawn (`ThemedSliderKeepsItsTrackFrame`). **JUDGE BUTTONS FOLLOW THE POSITION, BARS DO NOT** (`MainWindow.UpdateJudgeControlVisibility`, AO2's `Courtroom::show_judge_controls`): only the 4 verdict buttons + 4 health steppers hide off-judge; the rule is (1) `JD#` server override — `AOClient.JudgeControlsState`, 1 = show anywhere, 0 = hide, -1 = follow position — then (2) `Background.IsJudgePosition(CurrentOrDefaultSide)`, the background `design.ini` `judges=` list with hard-coded `jud` as fallback (`AOApplication::get_pos_is_judge`), tested against the CURRENT OR DEFAULT side so a character whose own side is a judge pos qualifies. A layout-hidden panel stays hidden (`OceanyaPanelEditModeController.IsHiddenByLayout` is public for exactly this). **IN-PANEL LISTS: also hide the popup's resize GRIPS** (`SetPopupResizeGripsVisible`) — dragging one re-fixes the surface size and re-breaks the stretch. **JUDGE CONTROLS + SHOWNAME TOGGLE:** `judge_defence/prosecution_bar` are image panels repainted from `defensebar0..10`/`prosecutionbar0..10` on `AOClient.OnHealthChanged` (`HP#<bar>#<value>#%`, bar 1 = defence, bar 2 = prosecution, 0-10, out-of-range IGNORED like AO2); `judge_*_plus/minus` call `AOClient.SetHealth` which only ASKS (the server echoes); `judge_witness_testimony/cross_examination/not_guilty/guilty` call `AOClient.SendCourtroomAnimation` (`RT#testimony1`, `testimony2`, `judgeruling#0`, `judgeruling#1`); `ic_check_showname` ← `showname_enable` sets `AOClient.SendCustomShowname`, which makes `ResolveShowNameForPacket` return empty rather than clearing the showname box. **THEMED SCROLLBAR NEEDS `ViewportSize`** — `Track` does not resolve it automatically, and without it the thumb has no size, which reads as "the list has no scrollbar"; the style also has a Horizontal orientation trigger. **In-window lists must clear their popup surface's fixed Width/Height** (`ApplyListRenderInPanel`) or the content cannot follow the panel and the inner list has nothing to scroll; the size is restored when handed back to the popup. **LABEL PADDING CLIPS TEXT:** a WPF `Label` defaults to 5px padding on every side (Qt has none), which ate 10px of a themed panel's height and cut the bottom half of the glyphs — setting a font now drops `Label.Padding` (tracked via `Control.PaddingProperty`). **CHECKBOXES ARE LAYERED:** Qt draws the widget's `image` across the whole widget (caption art including an empty box, e.g. `pre.png` 65x15) and `::indicator` (15x15) OVER it at its own pixel size, left-aligned — side-by-side layout showed the symbol twice. **FONT HEIGHT ONLY GROWS:** AO2 widget geometry owes nothing to its font, so `ApplyFont` takes `max(layoutHeight, fontHeight)`; shrinking clipped every panel a theme sized deliberately. **`Visibility` and `Content` are deliberately NOT baseline-tracked** — runtime code owns them (placeholder captions, hosts filled in code), and restoring a captured value put the "OOCName" placeholder back over a real showname; styling that touches them registers an explicit `PanelStateOverrides` undo (also true for `ColumnDefinition.Width` and hidden glyph visibility, neither of which is in the element walk). **GLYPH FACES REPAINT:** `SetGlyphFaceArt` paints the first `Panel` in the face unconditionally (an early `Background == null` guard meant hover art could never replace the base art) and hides the icon-font TextBlocks with an undo. **`themedScrollBarStyle` is `[ThreadStatic]`** — a WPF Style belongs to its creating thread and this app has more than one UI thread (WaitForm). **`[PANEL-LAYOUT]` diagnostic** (Viewport category, after every layout apply) lists panels that ended up hidden/zero-sized/off-surface — use it when a user reports "that part of the window is gone".
