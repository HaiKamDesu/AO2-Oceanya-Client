# webAO asset fallback, mirroring and character streaming

## select character popup slow

**Also called:** "select character popup slow", "inipuppet picker takes forever", "character selector lag", "too many characters", "characters say I don't have them but webao does"

**Status:** Confirmed

`OceanyaClient/Components/Forms/CharacterSelectorWindow.xaml(.cs)`. Cost on a big server was per-card work in the constructor: a fresh 60x60 `WriteableBitmap` placeholder PER CARD, a SYNCHRONOUS `BitmapImage` decode per icon, and one hidden 1x1 automation `Button` per character. Now: `SharedPlaceholderIcon` (one frozen static), `IconCache` (static, path-keyed, last-write-time validated, frozen, `DecodePixelWidth`-limited, `IconCacheCapacity` 4000), icons decoded on a worker and applied in `IconBatchSize` (48) dispatcher batches via `StartBackgroundIconLoad` (cancelled by `CancelIconLoading` on rebuild/close), and automation buttons built ONLY when `OceanyaTestMode.IsEnabled` (FlaUI still gets them). Timing: `[CHARSELECT-TIMING] total=… | localIndex=… entries=… cards=… automation=… select=… | serverChars=… cards=… localChars=… webOnly=…` and `[CHARSELECT-ICONS] loaded=… decoded=… cacheHits=… elapsedMs=…`, both under `LogCategory.Viewport` (`[VPT]`). Web parity: `CharEntry.IsWebOnly`/`IsSelectableSource` mean a character the server can stream is fully selectable and styled identically to a local one; only `IsProvenAbsentOnServer` (characters.json says it does not exist) still greys a row out. Selecting a streamed character routes through `MainWindow.EnsureCharacterAvailableLocallyAsync` -> `WebCharacterMirror.EnsureCharacterAsync` (fetches `char.ini`, upserts the folder) behind a wait form. Both selector entry points (`ShowCharacterSelectorForClientSelectionAsync`, `ShowCharacterSelectorForAvailability`) show a wait form while building.

## web assets slow

**Also called:** "web assets slow", "13 second asset latency", "webao icons never load in char select", "avgMs huge", "asset pipeline saturated", "3564 characters"

**Status:** Confirmed

Measured on skrapegropen (3564 characters missing locally): mirroring the whole roster's `char.ini` at connect issued 3564 prefetch downloads, saturated the pipeline for 2+ minutes and gave `[WEB-SUMMARY] avgMs=13149 maxMs=52832` (queue wait, not network) while `reqPerAsset=1.07` proved learned formats were fine. **Never bulk-mirror the roster** - `WebCharacterMirror` is on-demand only (`EnsureCharacterAsync` on selection + `CharacterSelectorWindow.WarmVisibleWebCards` for cards actually on screen, debounced on `ScrollChanged`). Second finding from the same log: 512 renders, 488 of them `[WEB-REFRESH]` repaints at 16-20ms each (~9s of UI stalls) because EVERY materialized `char.ini` repainted the scene; `AO2ViewportControl.IsSceneRelevantWebAsset` now drops Config/Sound/Blip/Music/CharacterIcon kinds and any character/background path that is not the one on screen. Web icons never appeared because `StartBackgroundIconLoad` only iterated cards with a non-empty `LocalIconPath` (web-only cards have none) and nothing re-applied a late icon; fixed by `CharacterSelectorWindow.OnWebAssetMaterialized` (applies `CharacterIcon` arrivals to the matching card) plus a mirror lookup for `CharIconPath`, which `CharacterFolder` resolves ONCE at `Create` time and therefore leaves empty for a character registered before its icon downloaded.

## webao sprites not showing

**Also called:** "webao sprites not showing", "placeholder sprites but webao shows them", "single sprite character", "webp.static", "extensions.json only .webp"

**Status:** Confirmed

miku.pizza publishes `emote_extensions: [".webp", ".webp.static"]`. Collapsing `.webp.static` into `.webp` left ONE candidate, so `(a)brokentalk.webp` 404'd and nothing else was tried - while the real file is `brokentalk.webp` (prefix dropped), which returns 200. `.webp.static` is now preserved through `WebAssetManifest.NormalizeExtensionList` and expanded by `WebAssetFetchQueue.BuildCandidate`/`StripEmotePrefix` into the prefix-less `.webp` candidate. Also: manifest keys that map to the same kind (`charicon_extensions` + `emotions_extensions` -> CharacterIcon) now MERGE instead of last-one-wins. Second half of the bug: the 24h persisted negative cache had recorded ~250 misses under the broken single-candidate list and kept suppressing them afterwards, so the fetch-queue cache key now includes `BuildProbeSignature(kind)` - the SORTED configured extension set, deliberately not the learned-reordered one (folding in learned order would make every `InvalidateLearned` flip the key and re-probe absent assets forever). Tests: `Manifest_KeepsWebPStaticAsADistinctCandidate`, `StripEmotePrefix_RemovesOnlyALeadingAo2EmotePrefix`, `FetchQueue_WebPStaticResolvesThePrefixlessSprite`, `FetchQueue_NegativeCacheDoesNotOutliveAProbeListChange`.

## web character has no icon in clients panel

**Also called:** "web character has no icon in clients panel", "emote buttons blank for webao character", "char icon missing after selecting streamed character"

**Status:** Confirmed

`CharacterFolder` resolves `CharIconPath` and each emote's `PathToImage_on/_off` ONCE at parse time and persists them in the character cache, so a character registered from the mirror the instant its `char.ini` landed records EMPTY paths permanently. Display code therefore asks `OceanyaClient/Features/WebAssets/WebCharacterIconResolver.cs` (baked path -> mirror lookup -> fire a request), wired at `ICMessageSettings` character dropdown + `CreateEmoteButton`, and `MainWindow`'s client toggle-button icon. Emote buttons are `characters/<char>/emotions/button<EMOTE ID>_on|_off` - keyed by the numeric ID, NOT the emote name. `ICMessageSettings` subscribes to `WebAssetService.AnyMaterialized` and rebuilds the grid on a 400 ms debounce once art arrives.

## other people show placeholder sprites

**Also called:** "other people show placeholder sprites", "only my own character loads", "placeholder.gif for everyone else", "char=(null) in render log"

**Status:** Confirmed

Sprite resolution runs through `CharacterFolder`: `AO2ViewportAssetResolver.ResolveCharacterImageAsset` early-returns when `character?.Name` is empty, so with no local folder the viewport had no folder name to build `characters/<name>/(a)<emote>` from and drew `themes/default/placeholder.gif` EVEN THOUGH the sprites had already downloaded into the mirror (log signature: `Render character char="(null)" ... assetPath=...placeholder.gif`). Only the user's own character worked because selecting it mirrors its `char.ini`. Fix: `AO2ViewportControl.EnsureSpeakingCharacterMirrored` calls `WebCharacterMirror.EnsureCharacterAsync` for `message.Character`/`message.OtherName` when unknown (bounded to people actually speaking, NOT the roster) and then forces a repaint; `RefreshSceneVisualsForWebAsset` re-resolves `args.Character` from `args.Message?.Character` instead of replaying the captured null.

## server characters in main dropdown

**Also called:** "server characters in main dropdown", "iniswap to a character I do not have", "character combobox only shows local"

**Status:** Confirmed

`ICMessageSettings.SetServerCharacterRoster(roster)` (called from `MainWindow.AttachWebAssetFallback` on `AOClient.OnServerCharacterListReceived`) stores server names the user lacks in `serverOnlyCharacterNames` and `RepopulateCharacterDropdown()` appends them after the local ones. Session-scoped and gated on `WebAssetService.IsActive`, so the entries vanish on a non-web server (a roster arriving with fallback off clears the list). Icons are warmed VISIBLE-ONLY (`WarmVisibleDropdownIcons`, driven by `ImageComboBox.VisibleItemsChanged`): the popup uses `ScrollUnit="Item"` + `CanContentScroll="True"`, so `GetVisibleItems(margin)` derives the on-screen index range straight from the dropdown ScrollViewer's `VerticalOffset`/`ViewportHeight` - no container hit-testing. When an icon lands, `OnWebAssetMaterialized` updates that ONE row via `ImageComboBox.TryUpdateItemImage` (`DropdownItem` implements `INotifyPropertyChanged` on `ImagePath`); do NOT rebuild the list per icon, it can hold thousands of rows. Picking one routes through `ConfirmServerOnlyCharacterAsync` -> `EnsureCharacterAsync` before applying. Timing: `[CHARDROPDOWN-TIMING]`. `ReinitializeSettings` goes through the same rebuild so an asset refresh does not drop server entries.

## webAO

**Also called:** "webAO", "web assets", "asset URL", "ASS# asset_url", "stream assets from server", "AsyncAO", "I don't have that character but they do", "assets I don't have locally"

**Status:** Confirmed

`Documentation/WebAOAssetFallback.md`; code in `Common/WebAssets/*` (`WebAssetService` facade + static `Current`, `WebAssetSource` URL/VPath/mirror, `WebAssetFetchQueue` download, `WebAssetFormatMemory` learned formats + negative cache, `WebAssetManifest` root manifests, `WebAssetStats` counters). **Complete end to end; live-server verification still outstanding.** Core trick: web assets materialize into an AO2-shaped mirror at `<CacheEnvironment.GetCacheRoot()>/webassets/<hash>/` appended LAST to `Globals.BaseFolders`, so every existing first-hit-wins resolver prefers local files with zero code change and downstream consumers still get plain file paths. `Globals.UpdateConfigINI` must call `WebAssetService.ReapplyMount()` (rebuilding `BaseFolders` drops the mirror). Sync resolution NEVER touches the network - a miss returns null and fires `WebAssetService.RequestIfActive(...)`; the asset arrives via the static `AnyMaterialized` event, which `AO2ViewportControl` debounces (60ms) into `RenderScene(..., visualRefreshOnly: true)` (skips audio/shake/slide/sticker/evidence/text-reveal). Resolver hooks: `ResolveImageVfs`/`ResolveImageStem` take an optional `WebAssetKind` (null = layout probe, no traffic); `ResolveImageVfsCandidates` walks the WHOLE AO2 candidate list locally before requesting anything; `RequestWebBackgroundFallback` handles a bg with no local folder (needed because `Background.FromBGPath` requires a folder to exist first). Audio: SFX/blips/character-shout request on miss with NO grace window (a late sound is worse than silence); music untouched (BASS already streams the URL). Grace window: `StartQueuedMessageDisplay` may hold a message up to `WebAssetService.DefaultGraceWindowMilliseconds` (150ms) for a cold sprite, and ONLY when fallback is active and the sprite is genuinely missing - otherwise the path is fully synchronous as before. Install point: `MainWindow.AttachWebAssetFallback` off `AOClient.OnServerAssetUrlReceived` (GM-only; that is what keeps the Character DB Viewer physical-only), which also kicks `WebCharacterMirror.EnsureCharacterAsync` for on-demand `char.ini` mirroring. **Cache signatures must use `Globals.PhysicalBaseFolders`, never `Globals.BaseFolders`** (CharacterFolder/Background `IsCacheCompatible`+`SaveToJson`, `ClientAssetRefreshService` marker+scans). Reference sources: webAO `webAO/webAO/client/aoHost.ts` (AO_HOST from `ASS#`), `client/fetchLists.ts` (`characters.json`/`backgrounds.json`/`evidence.json`/`extensions.json`), `utils/filesExist.ts` (parallel extension probe), `viewport/utils/preloadMessageAssets.ts` (per-message preload); AsyncAO `AsyncAO/internal/assets/resolver.go` + `docs/adr/0001-zero-fallback-by-default.md` (learned formats). Gotchas: URLs escape like JS `encodeURI` NOT `Uri.EscapeDataString` (parens in `(a)normal` must stay literal); mirror written lowercase; `.webp.static` is a URL-SHAPE marker (webAO `setEmote.ts` drops the `(a)`/`(b)` prefix and appends `.webp`), NOT a decode hint - collapsing it to `.webp` broke every single-sprite character; `HttpClient` timeouts arrive as `TaskCanceledException` and MUST count toward the circuit breaker; **never add the mirror to `CharacterFolder.IsCacheCompatible`'s signature** or the 30 s cold rescan returns. Debug category `WebAssets` (`[WEB]`), `[WEB-SUMMARY]` `reqPerAsset` should trend to 1.0. Tests: `UnitTests/WebAssetFallbackTests.cs` (stub `HttpListener` asserts request counts, not just behavior) and `UnitTests/WebAssetIntegrationTests.cs` (mount priority, `PhysicalBaseFolders` isolation, VPath mapping, menu provenance; WPF menu tests need `[Apartment(ApartmentState.STA)]`).
